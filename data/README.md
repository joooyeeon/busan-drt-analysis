# 데이터 형식

입력 CSV는 사용자가 준비합니다. `templates/`에는 빈 입력 양식만 들어 있습니다. 노선번호는 문자열로 읽으며 노선마다 날짜당 한 행을 사용합니다.

## 1. boardings_daily.csv

저장 위치: `data/boardings_daily.csv`

| 열 | 의미 | 형식·단위 |
| --- | --- | --- |
| `date` | 승차 기록 기준 날짜 | `YYYY-MM-DD` |
| `route_id` | 노선번호 | `520`, `180`, `36`, `10`, `68` |
| `boardings` | 해당 날짜의 승차인원 합계 | 0 이상의 정수, 명/일 |

분석 대상은 2025년 11월 평일 20일입니다. 다섯 노선이 모두 있으면 100행입니다. 날짜가 누락된 경우 실제 승차인원이 0명이었다고 자동으로 채우지 않습니다. 수요가 실제로 0명인 날은 근거를 확인한 뒤 0을 명시합니다.

## 2. routes_daily.csv

저장 위치: `data/routes_daily.csv`

이름에 `daily`가 들어 있지만 **날짜별 표가 아니라 노선별 한 행의 입력 표**입니다. 한 노선의 모수는 분석기간 동안 동일하게 적용합니다.

| 열 | 의미 | 형식·단위 |
| --- | --- | --- |
| `route_id` | 노선번호 | 문자열, 중복 없이 5개 노선 |
| `label` | 화면에 표시할 노선명 | 예: `520번` |
| `n_buses` | 현재 투입 버스 대수 | 양의 정수, 대 |
| `operating_min` | 하루 운영시간 | 양수, 분/일 |
| `tau_p_min` | 평균 픽업 이동시간 | 양수, 분 |
| `tau_b_min` | 평균 승객 수송시간 | 양수, 분 |
| `tau_e_min` | 평균 빈차 재배치시간 | 양수, 분 |

`tau_p_min`은 평균 대기시간 상한 10분보다 작아야 서비스 통과안을 찾을 수 있습니다. 양식의 빈칸은 실제 자료 또는 연구에서 정한 가정값과 그 근거로 채웁니다. 운영시간 추정만으로 다른 모수를 알 수는 없습니다.

## 3. TRN001 원자료

### 일별 승차인원 집계에 사용하는 열

| 원자료 열 | 사용 방식 |
| --- | --- |
| `행데이터기준일자` | `YYYYMMDD`로 해석, 2025년 11월 평일만 사용 |
| `승하차상태(탑승회차-승차:0/하차:1)` | `-0`으로 끝나거나 `0`인 승차 기록만 사용 |
| `노선번호` | 대상 5개 노선으로 제한 |
| `운수업체명칭` | `지하철` 또는 `도시철도`가 포함된 기록 제외 |
| `탑승인원` | 숫자로 변환한 뒤 날짜·노선별 합산 |

집계 코드는 `utf-8-sig`, `cp949`, `euc-kr` 순으로 인코딩을 확인하고 50만 행씩 읽습니다. 원본 방식에 따라 숫자로 변환되지 않는 `탑승인원`은 0으로 처리합니다.

이 코드의 교통수단 구분은 **대상 노선번호와 운수업체명 기준**입니다. `차량번호 = 0`을 직접 제외하는 로직은 포함되어 있지 않습니다. 일반적인 전체 버스·마을버스 분류기가 아니라, 지정한 5개 노선의 집계 코드입니다.

### 운영시간 추정에 사용하는 열

`행데이터기준일자`, `승하차상태(탑승회차-승차:0/하차:1)`, `노선번호`, `카드사용시간`을 사용합니다. 원본과 같이 `utf-8-sig`로 읽으며, 노선번호와 승차 여부로 필터링합니다.

- `카드사용시간`은 HHMM 형식으로 해석합니다. HHMMSS 자료에는 그대로 적용하지 않습니다.
- 00:00~03:59 승차는 전날 운행의 연장으로 보고 운행일을 하루 앞당깁니다.
- 일별 첫 승차부터 마지막 승차까지의 간격이 300분 미만인 날은 제외합니다.
- 남은 일별 간격의 중앙값을 노선별 `operating_min`으로 제시합니다.

승차인원 집계는 원자료 날짜를 그대로 쓰고, 운영시간 추정은 위의 자정 이후 운행일 조정을 적용합니다. 두 처리의 날짜 기준은 동일하지 않습니다.

| 보조 출력 파일 | 주요 열 |
| --- | --- |
| `operating_time_daily.csv` | `service_date`, `route_id`, `first_min`, `last_min`, `operating_min` |
| `operating_time_summary.csv` | `route_id`, `first_min`, `last_min`, `operating_min`, `days`, `first_time`, `last_time` |

`days`는 운영시간 추정에 실제로 남은 날짜 수입니다. 이 값은 300분 기준 때문에 20일보다 작을 수 있습니다.

## 4. 결과 지표

| 열 | 의미 |
| --- | --- |
| `lambda_per_min`, `mean_lambda` | 분당 승객 도착률과 그 일별 평균, 명/분 |
| `current_bus_total_cost` | 현재 버스 대수 × 버스 1대 하루 비용 |
| `current_bus_fare_revenue` | 일별 승차인원 × 1,500원의 기존 버스 추정 수입 |
| `bus_avoidable_cost_70` | 현행 버스 총운행비 × 0.7 |
| `bus_net_cost_70` | 70% 회피가능 버스 운행비 − 기존 버스 추정 수입 |
| `min_M_service` | 평균 대기시간·이용유지율 기준을 통과하는 최소 DRT 차량수 |
| `mean_wait_at_min_M` | 최소 서비스 통과 차량수에서의 평균 대기시간, 분 |
| `retention_at_min_M` | 최소 서비스 통과 차량수에서의 이용유지율, 0~1 |
| `feasible_day` | 최소 필요 DRT 차량수가 현재 버스 대수 이내인지 여부 |
| `alpha_star_M` | 차량수 상한 없이 서비스 통과안 중 DRT 순비용이 최소인 차량수 |
| `alpha_star_day` | (위 서비스 통과안의 DRT 순비용 + 기존 버스 추정 수입) ÷ 현행 버스 총운행비 |
| `best_feasible_M` | 현재 버스 대수 이내의 서비스 통과안 중 DRT 순비용이 최소인 차량수 |
| `best_feasible_drt_net_cost` | 위 실현가능안의 DRT 순비용, 원/일 |
| `daily_saving_70` | 현행 버스 총운행비 × 0.7 − 기존 버스 추정 수입 − 최적 실현가능 DRT 순비용 |
| `economic_M_70` | 절감액이 양수일 때의 최적 실현가능 차량수, 그 외 빈값 |
| `weekday_days` | 실제 분석된 노선별 날짜 수 |
| `feasible_day_rate` | 분석된 날짜 중 차량수 조건을 통과한 비율 |
| `alpha_star` | 일별 `alpha_star_day`의 중앙값 |
| `economic_day_rate_70` | 분석된 날짜 중 서비스·차량수 조건과 양의 절감액을 만족한 비율 |
| `mean_daily_saving_70` | 실현가능안이 있는 날짜들의 평균 절감액, 원/일 |
| `median_daily_saving_70` | 실현가능안이 있는 날짜들의 일별 절감액 중앙값, 원/일 |
| `median_current_bus_fare_revenue` | 전체 분석 평일의 기존 버스 추정 수입 중앙값, 원/일 |

접미사 `50`, `100`도 같은 정의이며 회피가능 원가 비율만 다릅니다. 실현가능안이 없는 날의 절감액은 빈값이므로 평균·중앙값 계산에서 제외됩니다. 실현가능한 날의 음의 절감액은 포함합니다. 경제적 평일 비율의 분모에는 실현가능하지 않은 날짜도 포함됩니다.

## 5. F2 비용 검수표

`outputs_daily/F2_cost_check.csv`는 노선별 한 행입니다.

| 열 | 의미 |
| --- | --- |
| `bus_full` | 현행 버스 하루 총운행비 |
| `bus_fare` | 전체 분석 평일의 기존 버스 추정 수입 중앙값 |
| `bus_avoidable_cost_70` | 현행 버스 하루 총운행비의 70% |
| `bus_net_70` | 실현가능일의 70% 회피가능 버스 순비용 중앙값 |
| `drt` | 실현가능일의 최적 DRT 순비용 중앙값 |
| `median_daily_saving_70` | 실현가능일의 일별 70% 절감액 중앙값 |
| `required_M` | 전체 분석 평일의 최소 서비스 통과 차량수 중앙값 |
| `feasible_days`, `total_days` | 실현가능일 수와 전체 분석 평일 수 |
| `feasible` | 실현가능일이 하나 이상 있는지 여부 |
| `economic_days_70` | 전체 분석 평일 중 70% 기준 절감액이 양수인 날의 수 |

`bus_fare`와 `bus_net_70`의 집계 대상 날짜는 다를 수 있습니다. 비용 비교 그림의 두 점 차이로 일별 절감액 중앙값을 대신하지 않습니다. 이 표에서도 `50`, `100` 접미사는 해당 시나리오를 뜻합니다.
